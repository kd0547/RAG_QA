# 인증 자료 묶음 절차

## 절차

1. **요청한 인증과 모델을 찾는다.** graph_search에 인증 이름과 모델명을 넣는다. 상위 개념(예: KC 인증)이면 속한 인증 종류가 펼쳐진다. 시스템 프롬프트의 상위 개념 목록도 함께 본다.
2. **종류마다 문서를 찾는다.** graph_search가 돌려준 문서와 페이지를 먼저 본다. 부족하면 grep_documents로 모델명이나 인증번호 표기를 찾는다.
3. **인증서 페이지를 read_pages로 읽는다.** 종류마다 아래를 확인한다.
   - 인증 종류
   - 인증번호(신고번호·등록번호)
   - 발급기관
   - 발급일, 유효기간이 적혀 있으면 유효기간
   - 인증서에 적힌 적용 모델명
4. **적용 모델을 확인한다.** 인증서의 모델명이 질문의 모델과 정확히 같거나, 인증서의 파생 모델 목록에 질문의 모델이 있어야 한다. 확인되지 않으면 상태를 "확인 필요"로 둔다.
5. **찾지 못한 종류는 "문서 없음"으로 밝힌다.** 종류를 빼고 답하지 않는다.

## 지킬 것

- 상위 모델이나 비슷한 모델의 인증서를 질문한 모델의 것으로 쓰지 않는다. 그래프가 상위 모델의 문서를 후보로 주더라도 적용 모델은 인증서에서 확인한다.
- 인증번호와 발급기관은 문서 표기를 한 글자도 바꾸지 않고 옮긴다.
- 유효기간이 지났는지는 문서에 날짜가 있을 때만 말한다.
- 어느 문서 몇 쪽에 있는지 쓴다. 메일 답장에서는 "첨부합니다", "보내 드립니다"라고 쓰지 않는다 (붙일 파일은 검토 담당자가 승인할 때 고른다).

## 출력

1. 첫 문장: 확인된 종류 수와, 확인 필요·문서 없음이 있으면 그 수.
2. 표

| 인증 종류 | 번호 | 발급기관 | 적용 모델 | 문서 | 상태 |
|-----------|------|----------|-----------|------|------|

3. 표 아래: 확인 필요와 문서 없음 항목을 다시 짚는다.

- 상태는 "확인됨", "확인 필요", "문서 없음" 중 하나다.
- 문서 칸에는 문서명과 페이지를 쓴다. evidence_id는 표에 쓰지 않고 마지막 줄에만 쓴다.

# 반려 반영 절차

`[검토 담당자 반려]` 메시지의 사유를 아래 네 종류로 나누고, 종류에 맞게 처리한다. 사유가 여러 개면 각각 처리한다.

| 사유 종류 | 예 | 처리 |
|-----------|----|------|
| 문체·형식·길이 | "표를 빼고 두 문장으로", "더 공손하게" | 도구를 부르지 않는다. 이전 초안의 사실과 수치는 그대로 두고 표현만 고친다 |
| 삭제·범위 축소 | "발급일은 빼 주세요" | 도구를 부르지 않는다. 해당 내용만 뺀다 |
| 사실 오류 지적 | "인증번호가 틀렸습니다" | 아래 "사실 오류" 절을 따른다 |
| 누락 | "안전확인 신고도 넣어 주세요" | 빠진 항목만 새로 찾아 읽는다. 이미 읽은 근거는 다시 읽지 않는다 |

## 사실 오류

1. 담당자가 올바른 값을 적어 줬으면 그 값으로 고친다.
2. 적어 주지 않았으면 list_evidence로 근거를 확인하고, 해당 페이지를 read_pages로 다시 읽어 값을 확인한다.
3. 다시 읽어도 확인되지 않으면 그 내용을 빼고 "등록된 문서에서 확인하지 못했습니다"라고 쓴다.

## 지킬 것

- 지적받지 않은 부분은 바꾸지 않는다.
- 고친 부분만 쓰지 않는다. 완성된 답변 전체를 다시 쓴다.
- 반려 사유, "수정했습니다", "다시 작성했습니다"를 답변에 쓰지 않는다.
- 반려 메시지의 문장을 검색어로 쓰지 않는다.
- 마지막 줄의 근거는 다시 쓴 답변이 실제로 쓰는 근거만 남긴다. 이미 읽은 근거는 evidence_id로 다시 인용할 수 있다.

# 입찰 사양 대조 절차

## 절차

1. **조건을 먼저 모은다.** 첨부가 있으면 read_attachment로 사양이 적힌 페이지를 끝까지 읽는다. 잘렸으면 next_offset으로 이어 읽는다. 본문에 적힌 조건도 포함한다. 조건은 이번 질문의 첨부와 본문에서만 모은다. 이전 대화의 조건이나 대조 결과는 다시 쓰지 않는다.
2. **조건을 한 줄에 하나씩 나눈다.** "CPU i5 이상, RAM 16GB 이상"은 조건 두 개다. 요구 값은 원문 표기를 그대로 둔다.
3. **조건을 속성 키로 바꾼다.** list_spec_attributes로 속성 사전을 보고 조건마다 속성 키, 비교 방향, 값, 단위를 정한다. 맞는 속성이 없는 조건은 따로 적어 두고 6번에서 문서로 확인한다.
4. **대상을 정한다.** 질문이 모델을 지정했으면 search_spec_items에 모델명을 넣어 찾는다. 지정하지 않았으면 search_spec_items에 조건을 넣어 후보를 찾는다.
5. **compare_specs로 판정을 받는다.** 숫자 크기 비교와 단위 환산을 직접 하지 않는다. 도구가 돌려준 판정을 그대로 쓴다.
6. **사양 DB에 값이 없는 조건은 문서에서 찾는다.** grep_documents나 search_documents로 페이지를 찾고 read_pages로 읽는다. 문서에서도 찾지 못하면 확인 필요다.
7. **표로 답한다.** 조건을 하나도 빼지 않는다.

## 판정

| compare_specs 결과 | 답변의 판정 | 제품 값 칸 |
|--------------------|-------------|------------|
| met | 충족 | 기본 사양 값 |
| met_with_option | 확인 필요 | "옵션 ○○ 구성 시 충족"과 옵션 값 |
| not_met | 미충족 | 기본 사양 값 |
| unknown | 확인 필요 | 도구가 준 사유 (값 없음, 단위 확인 필요 등) |

지킬 것
- 추측하지 않는다. 비슷한 모델이나 상위 모델의 값을 가져다 쓰지 않는다. 상속된 값은 도구가 표시해 준 것만 쓴다.
- 사양 DB 값과 문서 값이 다르면 둘 다 적고 확인 필요로 둔다.
- 문서에서 읽은 값으로 판정할 때, 비교 방향이 없는 조건(예: "Wi-Fi 6 지원")은 문서에 같은 규격이 적혀 있을 때만 충족이다.

## 출력

조건을 모두 만족하는 모델이 없으면 "조건을 모두 만족하는 등록 모델이 없습니다"라고 쓰고, 미충족 핵심 조건 1~3개만 적고 끝낸다. 다른 모델로 대조표를 만들지 않는다. 아래 형식은 모든 조건을 만족하는 모델이 있거나 질문이 모델을 지정했을 때만 쓴다.

1. 첫 문장: 충족·미충족·확인 필요 개수.
2. 표

| 조건 | 요구 | 제품 값 | 판정 | 출처 |
|------|------|---------|------|------|

3. 표 아래: 미충족과 확인 필요 조건을 다시 짚는다.

- 출처 칸에는 "사양 DB" 또는 문서명과 페이지를 쓴다. evidence_id는 표에 쓰지 않고 마지막 줄에만 쓴다.
- 모델을 여러 개 대조했으면 모델마다 표를 따로 만든다.

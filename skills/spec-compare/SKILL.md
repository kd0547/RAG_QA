# 입찰 사양 대조 절차

## 절차

1. **조건을 먼저 모은다.** 첨부가 있으면 read_attachment로 사양이 적힌 페이지를 끝까지 읽는다. 잘렸으면 next_offset으로 이어 읽는다. 본문에 적힌 조건도 포함한다.
2. **조건을 한 줄에 하나씩 나눈다.** "CPU i5 이상, RAM 16GB 이상"은 조건 두 개다. 조건마다 항목, 요구 값, 비교 방향(이상·이하·일치·포함)을 정한다. 요구 값은 원문 표기를 그대로 쓴다.
3. **대상 제품을 정한다.** 질문이 모델을 지정했으면 그 모델만 본다. 지정하지 않았으면 graph_search와 grep_documents로 후보 모델을 찾는다. 후보가 여럿이면 모델마다 따로 대조한다.
4. **제품 값을 문서에서 읽는다.** 조건마다 grep_documents(정확한 표기)나 search_documents로 페이지를 찾고 read_pages로 읽는다. 검색 스니펫만 보고 값을 적지 않는다.
5. **조건별로 판정한다.** 아래 판정 규칙을 따른다.
6. **표로 답한다.** 조건을 하나도 빼지 않는다.

## 판정 규칙

| 판정 | 기준 |
|------|------|
| 충족 | 읽은 페이지에 제품 값이 있고, 기본 사양으로 요구를 만족한다 |
| 미충족 | 읽은 페이지에 제품 값이 있고, 요구를 만족하지 않는다 |
| 확인 필요 | 아래 중 하나에 해당한다 |

확인 필요로 두는 경우
- 값을 문서에서 찾지 못했다.
- 기본 사양인지 옵션인지 문서로 구분되지 않는다. 옵션으로만 만족하면 제품 값 칸에 "옵션 ○○ 구성 시"라고 적는다.
- 단위나 측정 기준이 달라 바로 비교할 수 없다.
- 문서의 모델명이 질문의 모델과 정확히 같은지 알 수 없다.

지킬 것
- 추측하지 않는다. 비슷한 모델이나 상위 모델의 값을 가져다 쓰지 않는다.
- 단위가 다르면 환산한 값을 함께 쓴다 (예: 1.5kg = 1,500g). 환산이 확실하지 않으면 확인 필요다.
- 비교 방향이 없는 조건(예: "Wi-Fi 6 지원")은 문서에 같은 규격이 적혀 있을 때만 충족이다.

## 출력

| 조건 | 요구 | 제품 값 | 판정 | 문서 |
|------|------|---------|------|------|

- 문서 칸에는 문서명과 페이지를 쓴다. evidence_id는 표에 쓰지 않고 마지막 줄에만 쓴다.
- 표 아래에 충족·미충족·확인 필요 개수를 한 문장으로 쓰고, 미충족과 확인 필요 조건을 다시 짚는다.
- 모델을 여러 개 대조했으면 모델마다 표를 따로 만든다.

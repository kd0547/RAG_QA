# C2-P7 메일 수신 스레드가 종료를 막지 않게

## 원인 확인 (코드)
- `mail/email_receiver.py` `fetch_new_emails`: `poplib.POP3_SSL(POP3_SERVER, POP3_PORT)`에 timeout이 없었다. `socket.getdefaulttimeout()`도 설정하는 곳이 없어(None) 연결·응답 대기가 무기한이다.
- `get_access_token`: `msal.PublicClientApplication(...)`에 timeout이 없었다. `acquire_token_silent`의 토큰 갱신 HTTP 요청도 무기한 대기할 수 있다 (msal 1.37은 `timeout`을 받아 `requests`에 넘긴다 — 소스 확인).
- 수신 루프 끝의 `stop_event.wait(60)`은 종료 신호에 바로 깨어나므로 원인이 아니다.
- 결론: 2026-11-13 10:38 종료 경고(`['mail-receiver']`)는 Outlook 장애 중 POP3 연결이나 토큰 요청이 무기한 대기한 것과 맞는다 (로그만으로 어느 쪽인지는 확정할 수 없다).

## 변경 파일
- `config.py`: `POP3_TIMEOUT_SECONDS=30`, `MSAL_TIMEOUT_SECONDS=30` (환경변수로 덮어쓰기)
- `mail/email_receiver.py`: `poplib.POP3_SSL(…, timeout=config.POP3_TIMEOUT_SECONDS)`, `msal.PublicClientApplication(…, timeout=config.MSAL_TIMEOUT_SECONDS)`. 대화형 로그인 흐름·스레드 데몬 여부는 그대로
- `tests/test_email_receiver_timeout.py`(신규)

## 결정한 것
- msal 시간 제한은 지시서의 30초를 별도 설정(`MSAL_TIMEOUT_SECONDS`)으로 두었다.
- **주의:** 종료 시점에 POP3가 응답 대기 중이면 최대 30초 걸리므로 `main.py`의 5초 대기 안에 끝나지 않을 수 있다 (경고 로그는 날 수 있지만 무기한 대기는 없다). 지시서대로 데몬으로 바꾸지 않았다.

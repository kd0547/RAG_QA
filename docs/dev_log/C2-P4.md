# C2-P4 검토 알림이 메일 처리 루프를 막지 않게

## 변경 파일
- `mail/email_service.py`: `notify_reviewer_async()` — `mail-notify` 데몬 스레드로 `_notify_reviewer` 실행. 처리 루프는 초안 저장 뒤 이 함수를 부르고 바로 다음 작업으로 간다. 알림 실패 로그 문구는 그대로
- `mail/email_send.py`: `send_email(…, timeout=None)` (None이면 `SMTP_TIMEOUT_SECONDS`=60)
- `config.py`: `NOTIFY_SMTP_TIMEOUT_SECONDS=20` (환경변수로 덮어쓰기)
- `tests/test_email_consumer.py`: 기존 테스트가 알림 스레드를 기다리도록 `join_notify_threads()`, 2건 추가. `tests/test_email_send.py`: timeout 전달 1건

## 결정한 것
1. 알림마다 스레드 하나 (큐·풀 없음). 메일 처리량(10초 주기, 단일 소비자)에 비해 충분하고 구조가 단순하다.
2. 승인 발송은 그대로 60초 (지시서대로).

발송 대역이 최대 5초 멈추는 동안 대기 작업 2건: 루프는 2초 안에 끝나고, 이벤트 순서가 `save:t1, save:t2, notify-done, notify-done`. 알림 2건 모두 실패(`send_failed`)해도 두 작업 모두 `drafted`. 알림 호출의 `timeout`은 20.

처음에는 시각(`time.monotonic`)으로 순서를 비교했는데, Windows 시계 해상도(약 15ms) 때문에 두 시각이 같아 전체 실행에서 실패했다. 그래서 이벤트 순서 기록으로 바꿨다.

## 확인하지 못한 것 / Gemini에게 요청할 검증
- 실제 Outlook 장애(TLS 핸드셰이크 시간 초과)에서 알림 스레드가 20초 안에 끝나는지는 실서버로 봐야 한다.

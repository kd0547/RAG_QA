# C2-P5 생성 실패 작업 재시도 API

## 변경 파일
- `storage/schema.sql`, `repository/repo_connect.py`: `task_reviews.action` CHECK에 `'retry'`. 마이그레이션은 A4의 재생성 방식으로, 허용 값(`TASK_REVIEW_ACTIONS`) 중 하나라도 CHECK에 없으면 재생성 (예전 `('reject')`, A4 시점 `('reject','mark_sent')` 모두 처리)
- `repository/task_repository.py`: `retry(task_id) -> bool` (failed → pending 조건부 UPDATE + `task_reviews` `action='retry', reason=NULL, requeue=1`), `latest_retry_id(task_id)`
- `app/routers/mails.py`: `POST /mails/{task_id}/retry` → 200 `{task_id, status:"pending"}` / 없으면 404 / failed가 아니면 409
- `agent/agent.py`: `run_agent_temp_attachments(…, retry_id=None)`. 대화 기록이 있고 반려가 없을 때
  - `_ended_without_answer()`: `get_state().next`가 비었고 마지막 AI 메시지가 비었거나 `Model call limits exceeded…`로 시작하거나 도구 호출이면 True → `[재시도] …` 메시지(ID `retry:{thread_id}:{retry_id}`)를 넣고 실행. label `메일 재시도(…)`
  - `next`가 남았으면 기존대로 `invoke(None)` 재개, 정상 답변으로 끝났으면 그 답변을 검증·저장 (C4 동작 유지)
- `mail/email_service.py`: `retry_id=task_repo.latest_retry_id(task_id)` 전달
- `frontend/src/mail/api.ts`, `MailReviewPage.tsx`: `retry` 반환 타입 `{task_id, status}`, 버튼 "재전송" → "다시 생성", 완료 문구 "다시 생성을 요청했습니다"
- `tests/test_retry.py`(신규), `tests/test_email_consumer.py`(대역에 `latest_retry_id`)

## 결정한 것
1. **재시도 메시지 ID의 n = 재시도 요청의 `task_reviews.review_id`.** 같은 요청을 두 번 처리해도 ID가 같아 덮어써진다. 요청 ID 없이 불리면(재시도 요청 없이 답변 없이 끝난 대화) 기존 재시도 메시지 수 + 1을 쓴다.
2. 재시도 기록(`action='retry'`)은 `unapplied_reject_reasons`가 `action='reject'`만 보므로 반려 사유로 잡히지 않는다 (테스트로 확인).
3. 검토 화면의 `failed` 상태 반려 버튼은 손대지 않았다 (지시서 범위 밖. 백엔드가 409로 막는다).

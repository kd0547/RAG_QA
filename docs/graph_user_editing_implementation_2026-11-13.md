# 그래프 사용자 개입 기능 구현·검증 기록

작성일: 2026-11-13. 기준: 같은 날짜의 개발 계획서·사전 판단서.
운영 서버 재시작·운영 DB 이관·실제 LLM 호출·메일 발송은 수행하지 않았다.

## 구현 범위

- 독립 객체 생성, 이름/표시명·별칭 편집, 삭제 영향 조회, 그래프 제외·복구.
- 기존 7개 객체 종류 유지. 관계 종류는 서버 레지스트리에서 조회하며 사용자 종류를 등록·비활성화할 수 있다. 연결 종류·방향·자기 연결 규칙을 서버에서 검사한다.
- text/number/boolean/date/enum 속성 정의와 값 CRUD, 단위·선택지·단일/복수 값·입력 한도 검사. 사용자 확정/미확정/명시적 미지원을 구분한다.
- 객체·수동 관계·속성의 삭제 상태, revision 충돌(409), 멱등 요청 키, 변경 전후 및 인증되지 않은 담당자 표시·세션·요청 이력.
- 사용자 생성/편집 객체를 자동 정리에서 보호한다. 삭제 ID와 병합 source ID는 보존하며 재추출 시 기존 ID 또는 병합 대상 ID를 찾는다.
- 수동 관계의 문서 참조를 `graph_fact_source`로 분리한다. 원본 파일 삭제 후에도 관계·이력·파일 이름·선택 페이지·가능한 페이지 스냅샷을 보존한다. 문서 선택을 검증 완료로 취급하지 않는다.
- `effective_graph_entity`/`effective_graph_relation`을 화면과 Graph RAG의 공통 읽기 기준으로 사용한다. 자동 관계의 출처별/논리 관계 전체 제외를 구분한다.
- 그래프 속성 텍스트·속성명 검색, `read_graph_facts` 읽기 전용 도구, 실제 반환된 확정 사실의 evidence 등록. 큰 결과는 `next_offset`으로 나누며, 미확정 값만 읽었을 때에는 근거 ID를 만들지 않는다.
- 과거 evidence는 보존한다. 수정·삭제·출처 상태가 달라진 스냅샷을 재인용하면 검증 오류와 재조회 안내를 낸다. 근거 목록에는 사용자 입력과 당시 버전을 표시한다.
- 화면 상단 객체 추가/속성 정의/관계 종류/변경 이력/삭제된 항목, 속성 자료형별 입력기, 출처 표시, 객체·수동 관계 복구를 제공한다. 알 수 없는 관계 키는 원래 키로 표시한다.
- 제품·부품은 기존 사양 DB 항목을 검색하여 명시적으로 연결하거나 그래프 객체만 만들 수 있다. 기술 사양과 구성 변경은 기존 사양 화면/API로 이동하며 연결된 대상을 바로 선택한다. 사양이 관리하는 관계를 수동 관계로 잘못 덮어쓰는 요청은 거부한다.

주요 구현: `repository/graph_migration.py`, `graph_rag/edit_service.py`, `repository/graph_repository.py`, `app/routers/graph.py`, `frontend/src/knowledge/`, `tools/tool.py`, `agent/validation.py`.

## U0 현황 및 이관 표

원본 `storage/mail.db`는 읽기 전용 SQLite 연결로 복사했다. 실제 SQLite는 **3.42.0**이며, 해당 운영 DB에는 기존 사양 ref 확장도 아직 적용되어 있지 않았다. 따라서 이전 origin/ref 마이그레이션과 신규 사용자 편집 이관을 함께 사본에서 확인했다.

| 항목 | 이관 전 | 이관 후 | 보존 방식 |
| --- | ---: | ---: | --- |
| 객체 | 59 | 59 | ID·이름·정규화 키 보존, 미상 출처 legacy |
| 별칭 | 96 | 96 | 기존 식별 표기 보존 |
| 관계 | 31 | 31 | 관계 ID·양 끝·종류·작성 시각 보존 |
| 추출/수동/seed 관계 | 28 / 1 / 2 | 28 / 1 / 2 | 출처별 보존 |
| 기존 차단 | 5 | 5 | 정규화 규칙 보존, 연결 가능한 안정 ID 제외 추가 |
| 파일 FK에 연결된 수동 관계 | 1 | 0 | 수동 사실은 유지하고 파일 참조를 출처 행으로 이동 |

검증 사본: `temp/graph-edit-rehearsal-final-20261113.db`.
반복 초기화의 동일성, 수동 ID, 별칭, 차단, 외래키 검사를 통과했다. 합성 구형 DB에서는 같은 triple이 서로 다른 파일에 연결된 수동 관계 ID 501/502의 동시 보존과 중간 DDL 실패 롤백도 검증한다.

재실행 방법(대상 파일은 없어야 함):

```powershell
.venv/Scripts/python.exe scripts/graph_edit_rehearsal.py --source storage/mail.db --target temp/new-graph-rehearsal.db
```

## 기존 계약에서 달라진 점

1. 근거 파일 삭제 시 수동 관계도 삭제하던 테스트를 **수동 사실·출처 스냅샷 보존** 테스트로 변경했다.
2. 동일 triple의 추출 주장과 사용자 주장이 공존한다. 파일을 NULL로 바꾸며 기존 유일 인덱스로 합치거나 버리지 않는다.
3. 화면/API의 수정·삭제는 `expected_revision`이 필수다. 병합에는 대상 객체의 `target_revision`도 필요하다. 이전 클라이언트는 409 뒤 새로고침해야 한다.
4. 기존에 허용되던 잘못된 객체 종류/방향의 관계는 서버에서 거부한다.
5. 별칭 삭제는 표시 목록에서 숨긴다. 재추출 중 중복 객체 생성을 막기 위해 과거 식별자로는 보존한다. 병합은 물리 삭제가 아니며 source ID에서 target ID를 추적할 수 있다.
6. 자료형·단위·연결 규칙을 바꾸는 의미 변경은 기존 정의의 제자리 변경을 거부하고 새 정의 등록·값 이관으로 처리한다. 라벨/설명/활성 상태 변경은 revision을 검사한다. 자동 이관 마법사는 포함하지 않았다.
7. 사양 관계의 그래프 제외는 `parent_id`/`product_component`를 바꾸지 않는다. 실제 연결 변경은 기존 사양 저장 경로와 동기화를 사용한다.

## 검증

- pytest 전체 **493개 통과** (70.82초). 마지막 seed 출처 표시 보완 후 그래프 관련 **60개 재검증 통과** (14.75초).
- 숫자 저장 범위 경계(64비트 정수 초과·부동소수점 범위 초과) 보완 후 사용자 편집 인수 테스트 **30개 통과** (20.00초).
- TypeScript `tsc -b`, 전체 ESLint, Vite build 통과. 기존 대형 번들 경고(500 kB 초과)는 남아 있다.
- 브라우저 직접 확인: 임시 DB에 독립 객체 2개 생성 → 사용자 text 속성 정의·값 저장 → 사용자 관계 종류 등록·연결 → 객체 제외 영향 확인 → 삭제 목록 → 동일 ID 복구. 콘솔 오류 없음.
- 화면 증거: `temp/graph-user-editing-ui.png` (검증용 데이터).
- 실제 LLM/메일 대신 테스트 대역을 사용한다. 미리보기 서버는 `scripts/graph_edit_preview.py`로 운영 DB와 분리하며 `/graph/rebuild` 실행도 차단한다.

## 운영 반영 및 롤백 경계

`GRAPH_EDIT_ENABLED=0`이면 모든 사용자 편집 API와 UI 쓰기를 중단하고 기존 읽기는 유지한다. 입력 한도는 `GRAPH_EDIT_NAME_LIMIT`(100), `GRAPH_EDIT_TEXT_LIMIT`(4000), `GRAPH_EDIT_PROPERTY_LIMIT`(50)으로 설정한다.

현재 구현은 **서버가 새 코드로 DB를 열 때 자동 이관**한다. 운영 반영 전에는 DB 및 문서 출처, 현재 미커밋 작업을 별도 보관한 뒤 새 버전을 시작해야 한다. 이번 작업은 그 운영 반영을 실행하지 않았다.

이전 코드로의 단순 롤백은 지원하지 않는다. 구버전의 파일 기반 유일 인덱스는 출처별 수동 관계가 여러 개 존재하는 새 DB에서 충돌할 수 있고, 구버전 조회는 soft delete도 해석하지 못한다. 데이터 문제가 생기면 먼저 기능 스위치로 쓰기를 끄고 신규 스키마를 이해하는 코드에서 수정한다. 운영 전 백업 복원은 복원 시점 이후 사용자 입력을 잃는 별도 작업이므로 코드 롤백과 구분해야 한다.

2차 범위(새 객체 분류, 관계의 임의 속성, 대량 가져오기, 동적 종류의 AI 자동 추출·추론)는 구현하지 않았다. 기존 미커밋 App/skill/사양 도구 수정 및 사용자 파일은 보존했고 커밋은 생성하지 않았다.
